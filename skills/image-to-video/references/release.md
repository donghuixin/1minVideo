# 从待配音版到发布版

**先辨别输入。** 没有录音：保持画面母版和外置字幕为草稿，交纯口播 TXT 供录音。已有与母版等长的混音 WAV：用 `cut.py mux` 原样复制画面。新到的自然语速 MP3/WAV 与分镜不同：用下面的实录路径，先改切点再考虑轻微变速。不先把整条音频拉到视频长度。用户要保留画面每一帧时，不用重新编码的 conform 路径。

### 实录路径

1. 听录音或在本地转写，逐段与画面对照，人工或助手核对产品名、单位和数值。语音可能改写了开头、顺序和结论；**不从稿子猜实际说了什么**。长停顿只能提议分段，不等于一句或一镜。缺乏可靠时间标记时先标待核，不把自动检测结果当作已核对。
2. 用 render 的导出目录（`picture.mp4`、`timing.json`）和录音做输入。若源片不是本工具生成的，先从原工程导出同帧率恒定帧率的画面和实际镜头边界；不要从字幕时长猜边界。只用已经核实的效果音，不把旧版旁白当作效果音保留下来。
3. 由助手填写 `take.json`。示例是「一个不出声的开场镜头、两个讲解镜头」；科普片可从第一镜就讲，此时 `opening_shots` 为 0。声音文件路径相对该 JSON。`in/out` 是**原始录音**里的秒数，不含视频开场，不是变速后的时间。

```json
{
  "audio": "assets/final-take.mp3",
  "opening_shots": 1,
  "opening_audio": "assets/opening-sfx.wav",
  "rate": 1.0,
  "cues": [
    {"in": 0.08, "out": 2.4, "text": "先看左边这张图。"},
    {"in": 2.8, "out": 5.6, "text": "两张图的拍摄角度不一样。"}
  ]
}
```

4. 运行 `python3 scripts/conform.py PROJECT/export PROJECT/take.json PROJECT/release-v2`。默认不变速；明确需要时，用 `rate` 保持音高地调整节奏。先把录音开头不想要的空白裁掉再标时间；工具将文件第一个采样放在开场末端，**不会假设它就是第一个音节**。`opening_audio` 可省略；提供时从其开头保留至开场末端，短者补静音。若通知声应在气泡入场时响，先按入场帧做好开场效果音轨，不要给每个场景默认配一声。该命令不自动识别语音，不添加音乐，不合成新音效。
5. 工具保留原总帧数及开场长度。一条实录 cue 对应后续一镜；新镜头从对应语句起点附近的整帧开始。延长的画面停在末帧，缩短的画面按比例压缩。若一段话要切两镜、动作不能压缩、语音有无关段落，先按内容编辑再导出，不硬塞。录音过长会报错，不截掉句尾。发布目录不可覆盖已有版本。
6. 交 `final.mp4`（不烧字幕）、`narration-clean.txt`（只含实录文本）、`picture-and-voice.txt`（画面时间对照）、可选 SRT/VTT、`aligned-mix.wav` 和编辑记录 `release.json`。旧试音、草稿字幕、历史导出不混入当前发布文件。图片、音效、录音及复剪所需脚本放在私人项目的持久目录，不依赖下载缓存或临时目录长期存在。

### 封面

写一个四行简报再作图：**观众学到什么**（标题原文）、**演示用什么例子**（副文案，可无）、**视觉方向**（画幅、颜色、标题/角色/参考图的主次）、**不得暗示什么**（如未演示的能力、未测量的结果）。交给图像工具的是这份简报，不是视频首帧的文字识别结果。缩到约 200 像素宽验收：第一眼读到的是主题还是案例？只需改颜色和主标题时不动已认可的正片；装饰性角色不代替真实产品操作。科普片也一样：不能把示意图的效果写成实验证明。

### 验收

核对编码文件，不只看脚本执行成功。记录总时长、画幅和实际音视频流；在首个发声音节、切镜前后、最后一句尾音抽查。预期“仅音效”时对比开场与参考音轨，不能仅检测开场是不是静音。抽查操作名说出口时对应按钮可见、字幕没有早于允许时点、字幕来自实录而非稿件、最后一个字没被截。封面是否正确看缩略图，不以分辨率合格代替内容检视。未经试听，只报告实际做过的音频测量/转写检查。
